# ChainDrop loader swapped Node for a self-downloaded Bun runtime and respawned itself detached

- Date: 2026-08-04 | Agent/tool: npm packages (keyv, flat-cache, cache-manager, cacheable family, ecto; 400+ packages affected) | Axis: evade
## What happened

On August 4, 2026, a threat actor pushed malicious commits to hundreds of npm repositories — starting with `keyv` and spreading to `cacheable`, `flat-cache`, `cache-manager` and others, some with over 150 million weekly downloads — and published trojanized versions through the projects' own GitHub Actions, complete with genuine SLSA provenance. Every package's `preinstall` ran a small loader, `setup.mjs`, whose entire job was to start the second stage under Bun instead of Node: it accepted any installed `bun`, or silently downloaded the official Bun v1.3.13 release zip from GitHub (unverified, following up to five redirects to any host), extracted it with system `unzip` into a `bun-dl-*` temporary directory, chmod'd it 0755, and exec'd the payload with it. The second stage — packed into two physical lines behind a 4,613-entry Base91 table with 73 unique alphabet permutations — respawned itself detached outside CI (`detached: true`, ignored streams, parent exits) with a mutex lock and no-op SIGINT/SIGTERM handlers, so collection outlived the `npm install` that started it. It swept 469 filename patterns (env files, shell histories, SSH material, AI assistant credentials, `/etc/shadow`), `process.env`, `gh auth token`, GitHub runner memory via `sudo python3` reading `/proc/<pid>/mem`, AWS Secrets Manager and SSM across 17 regions, Kubernetes secrets and Vault. Its C2 domain came from an `eth_call` to an Ethereum contract across 73 public RPC endpoints, the encrypted loot left over HTTPS or via a fresh public GitHub repository ("Shai-Hulud: Here We Go Again"), and any HTTP 200 response body was passed to `eval()` — turning the implant into a general remote code-execution channel. Propagation reused stolen npm tokens (replacing the whole `scripts` object with the loader) and wrote `.claude/settings.json` SessionStart hooks and `.vscode/tasks.json` folder-open tasks to up to 50 branches per repository.

## How it went wrong

The process tree is short and every hop wears a legitimate face: `npm install` → `node setup.mjs` (a normal-looking lifecycle script) → `bun --version` → `unzip` into a temp directory → `bun <stage2>` → a detached copy that survives the install finishing. The runtime substitution is the core trick: monitoring that is bound to Node.js runtime internals — hooks, instrumentation, or policy that reasons about "node" processes — sees nothing, because the code no longer runs in a Node process at all; the loader even preferred whatever `bun` was already on the machine and never cryptographically verified what it downloaded, with no origin restriction after a redirect. The detached respawn plus `_NODE_RUNTIME_INIT=1` recursion guard means the long-running malicious process is not even a child of the npm invocation a user might associate with the incident. Repository-level sleight of hand hid the operation from maintainers: signed `github-actions[bot]` commits added execution hooks to five branches, an unsigned commit reset the release branch non-fast-forward to keep the payloads while dropping the visible hooks, the test that directly invoked the loader was deleted while `preinstall` stayed, and the package published with real SLSA provenance generated by the project's own compromised workflow.

## What the firewall should learn

Every hop is an exec event the ptrace monitor already sees; what is missing is the chain. No single rule today connects exec(node, setup.mjs under npm ancestry) → exec(unzip, target under /tmp) → exec(bun, /tmp path) → parent-exits-while-child-continues — that is the write-then-exec-then-orphans pattern plus an interpreter that appears on no allowlist. Concrete rule ideas: an exec of any interpreter runtime (node, bun, deno, python) whose exe resolves to a temp directory or a path downloaded or unpacked earlier in the session is approval_required regardless of program name, so "swap the runtime" stops being a policy boundary; an unzip/tar extraction whose destination later appears as an exec exe path escalates; and activity continuing from a tracee whose ancestry root has exited should escalate toward terminate, since the detached respawn is the whole persistence trick. The C2 `eval(responseBody.code)` loop is a downloaded-string eval executed inside Bun, so interpreter-agnostic text rules (not node-specific hooks) are required to see it. Finally, the branch-propagation payloads land in exactly the agent-configuration files (.claude/settings.json SessionStart, .vscode/tasks.json runOn:folderOpen) that a firewall must treat as executable code, not as settings.
